# Support

## Where to ask

| You want to | Go to |
| --- | --- |
| Ask a question about using Caddi | **GitHub Issues** on this repository; start the title with "Question:" |
| Report a reproducible bug | **GitHub Issues**, using the bug report form |
| Suggest a feature | **GitHub Issues**, using the feature request form |
| Report a vulnerability | Privately, through the **Security** tab. See [SECURITY.md](SECURITY.md) |

## Before you ask

Most questions are answered by the guides at [caddi.build/docs](https://caddi.build/docs), the [FAQ](https://caddi.build/faq), and in this repository [README.md](README.md), [docs/CONNECTING-AGENTS.md](docs/CONNECTING-AGENTS.md) and [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

When you ask, include:

- how you run Caddi (the signed build, from source, or a bundle you packaged),
- the Caddi version or the commit you are on,
- your Mac model and macOS version,
- the coding agent involved, if any, and its version,
- what you did, what you expected and what happened instead.

Never paste a password, token, cookie or anything from a real account. Reproduce on a test page where you can.

## What maintainers help with

- Bugs in this source, including the browser, the local MCP server, Annotate and packaging.
- Documentation that is wrong, missing or misleading.
- Questions about how a feature or an MCP tool is meant to behave.

## What is yours to run

- **Your coding agents.** Caddi sets up the connection, but each tool's own install, sign-in and behaviour belong to that tool.
- **Your accounts and data.** Caddi has no account and no sync service, so there is nothing on our side to restore. Keep your own backups.
- **Your modifications.** A fork or a changed protection is supported by whoever made it.

Caddi is an early development preview. Support is best effort from a very small team, with no service level agreement.
